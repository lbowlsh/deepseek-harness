# 故障处理报告：lbowl 既有 doc-sync 门禁失败（2026-08-26）

> 故障编号：INC-2026-08-26-02
> 本报告为 `lbowl` 分支上既有 `pnpm run doc-sync` 失败的事实落盘与修复指引；证据采集于提交 `0ad9f0edbb`（INC-2026-08-26-01 落地之后），所有违例文件均非本次改动。

## 1. 故障概述

`lbowl` 分支全量 `pnpm run doc-sync` 共 28 个门禁，其中 7 个失败：markdown wrap、翻译配对、包 README 模型体验、包 README 已知限制、cordis 目录、client 目录、config 目录。经 `git merge-base --is-ancestor` 与 `git log` 核查，7 项失败全部为 lbowl 本地问题——违例文件或其引入提交在 `origin/master`（47f943859b）上均不存在或未过期。该故障与本目录 INC-2026-08-26-01（工具发射劫持）无关；`incidents/` 目录自身通过全部适用门禁（配对、markdown wrap、文档预算）。

## 3. 归因分析

- **一组根因（4 项门禁）**：lbowl 本地在制功能 `ui-git-history`（提交 2fbd4a0eff「feat(web): add git-history viewer plugin and host git api domain」）随包新增的 README 未按包 README 契约完成四项合规（单行段落、双语配对、模型体验、已知限制）。该功能尚未合入 master，故 master 无此问题。
- **另一组根因（3 项门禁）**：三个由生成器产出的目录（cordis/client/config catalog）在 lbowl 本地重构（`worktree-rename-team` 系列提交：Agent Teams 改名、experimental 包前缀化）与上游合并（release/dsh-0.1.0-rc.8 等）之后未重新生成。生成物是源码的投影，源码变更后必须重跑生成器并一并提交。
- **共同性质**：全部为 lbowl 分支过程性欠账，非 master 缺陷、非 incidents 目录引入。CI 在 lbowl 推送时会持续红，直到逐项修复。

## 4. 修复建议（逐项机械操作）

1. ui-git-history README 四项合规一次改齐：段落改一段一行（消硬换行）；补「## Known Limitations and Deferred Work」节或登记 NO_LIMITATIONS；补 model-context entries；补中文对照 `README.zh.md` 并 `pnpm run verify-translation-pairing --write packages/client/ui-git-history/README.md` 登记配对。
2. 重跑三个生成器并提交产物：`pnpm run gen-cordis-catalog`、`pnpm run gen-client-catalog`、`pnpm run gen-config-catalog`。
3. 修复后以 `pnpm run doc-sync` 全量复验；任一未绿不得宣称修复完成。
