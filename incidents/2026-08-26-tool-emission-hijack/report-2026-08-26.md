## 4. 根因结论（修正版）

1. **生成层责任成立**：chunk 流自证，平台/adapter/权限排除均成立。
2. **修正 1**：原始文档「仅单会话发病、故障=会话局部状态」不成立——同型病理跨 3 会话、跨 2 天复现，且与模型强相关（kimi-k3 全中，deepseek 系全无）。
3. **修正 2**：H1「该会话此前刚被合法调用过」的前提不成立——故障会话中该工具首次出现即循环本身（意图为原则 14 FP 审计读），无合法前置调用。但「零必填参数签名塌缩 + 自锁」的机制观察成立：该工具无必填参数，是唯一被锁定的目标。
4. **修正 3**：H2（告警反馈强化）与 H3（同族 schema 过载）弱化——告警不打断循环属实，但跨会话复现说明其仅为弱化因；deepseek 会话暴露相同 schema 族却零复现。
5. **主导根因**：**kimi-coding/k3 模型级 tool-call 选择缺陷**——在特定上下文（S3a 报价明细相关长任务、复杂写工具构造）下，模型反复塌缩到零必填参数工具并自锁；harness 侧告警机制按设计工作但为 advisory 不具强制力。触发阈值（上下文长度/调用轮次）待模型侧日志进一步确认。

## 6. 治理建议

1. **写前健康探针 + 熔断**（沿用）：任何写操作序列前先发轻量无害调用确认发射层健康；连续 2 次误发即熔断并停止写任务。
2. **模型侧规避**（新增，基于 §3.3）：kimi-coding/k3 会话执行写路径任务前强制探针；重要写路径任务优先使用 deepseek 系模型；观察到同型零参循环立即换会话。
3. **harness 硬熔断**（已落地，2026-08-26 提交 c993b39509）：`repeat-tool-reminder` 新增 `hardStop`——同一调用连续达到 `at` 次即派发前拒绝；部署按需 `hardStop.enabled: true` 启用（默认保持仅建议）。
4. **降级通道纪律**（沿用）：熔断后 `debug_sql`（confirm=true）直写必须按平台格式忠实补录事件审计行（本次 seq 17–20 为先例）。
5. **会话切换信号**（沿用）：跨回合未自愈即换会话；C1 当日经健康通道落地的实践佐证该纪律有效。
